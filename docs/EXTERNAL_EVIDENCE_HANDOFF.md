## Reproduce the operator workflow

Use the installed environment from the repository root. The default invocation
creates disposable temporary storage and prints a sanitized calculated summary:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/external_handoff_example.py
```

To retain the fictional artifacts locally, choose a **new** ignored directory:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B scripts/external_handoff_example.py \
  --output-directory .model-learner/w6b-demo
.venv/bin/model-learner learn advise \
  --input-file .model-learner/w6b-demo/advisory-input.json
```

The script refuses an existing output directory. It writes only there; no model,
candidate code, network, service, credential or Git operation is invoked. All
events and artifacts are original fictional fixtures. The dataset identity is
`synthetic-w6b-disposable-only`, version `1`. Its `source_kind=real` exercises the
existing real-contract builder/resolver solely in disposable fixture databases;
it is never personal execution evidence or a reclassified benchmark.

The reviewed fixture contract is exact data `42` followed by a newline, not a
coding benchmark. Its separately identified no-budget target is unrelated to
W4A's frozen 600-second target. One intentional wrong-data artifact exercises a
complete acceptance failure. No arbitrary Python is imported or executed.

## Receiving is not trusting

| State | Established here | Remaining limit |
| --- | --- | --- |
| Declared | Task/acceptance, configuration, execution bounds, completion, binding | Operator/source declarations do not authenticate an external process or model. |
| Received | Exact serialized metadata and local first availability | Imported timestamps are not authenticated historical time. |
| Validated | Supported identities/digests, approved intake, full segment and report/artifact/contract associations | SHA-256 proves content identity, not origin or independence. |
| Independently verified fixture | Known reviewed local data-only verifier generated the required acceptance report against the stopped fixture bytes | This trust is supplied by the reviewed choreography, not inferred from XML, exit code, hashes or an `observed` enum. |
| Unknown | Unsupported execution assurances, backend revision and resource measurements | They remain unknown; no learning-budget exception is introduced. |

`verify_junit` accepts operator report receipts; `import_bundle` and the canonical
schema do **not** authenticate verifier identity or independent control. A
self-consistent forged report plus forged declarations can pass structural
validation. Never give arbitrary producer-supplied Verification/Outcome records
the reviewed fixture's trust. The example rejects them; it is not a hardened
production intake/security boundary. Future real external handoff requires a
separately approved trust contract identifying the independent verifier and
evidence that the candidate cannot control its oracle, execution or report.
W6B does not implement that runtime or cryptographic attestation.

Source event/capture receipt, ingestion, receiver first receipt, report generation,
verification observation, assessment/derivation and forecast cutoff remain separate.
Missing/late receipt blocks earlier use despite old source times. A correction
adds a new assessment/receipt and changes current resolution without rewriting
retained forecasts. SQLite primary-record import does not install receipt-aware
semantics: use the retained sidecar with `resolve_bundle` for learning/advice.

Imports support an empty disposable destination or an exact scoped replay;
partial live merge and concurrent writers are refused. Validation/conflict checks
precede destination insertion; interrupted storage writes are not a transactional
live-merge guarantee. Retain source bytes and reconstruct a new disposable ledger.
Bundles contain selected metadata/digests, not artifact bodies, XML, private paths,
raw completion text, hidden test source, credentials or unrelated Tasks. Fixture
required test identities remain acceptance metadata. Human review is still needed
for public identifiers; no privacy policy/allowlist exemption was added.

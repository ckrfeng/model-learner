## Fixed contract and reuse

`model_learner.benchmark.supervision` reuses the existing versioned
`AcceptanceSpec` / `ExecutionConfiguration` contracts and the existing offline
adapter's bounded command runner, restricted container arguments and policy check.
It does not change those helpers, canonical records, receipt books, eligibility,
forecasts, estimators or advice. The new contract is
`synthetic-container-control/v1`, `source=synthetic_control_only`, target
`synthetic-supervised-data/1`; provider/model are absent. No Task/Run/Attempt is
created. Its UUID is a controller-run alias, not a canonical ledger record.

Only the dedicated existing Colima socket/profile and the installed immutable
ARM Alpine image are admitted. No pull, runtime setup, HTTP, credential loader,
caller code, alternate endpoint, custom image or model argument exists. Two fixed
reviewed workers are supported: normal output and a finite sleeping descendant
whose session is detached. Input is one original public synthetic constant,
materialized by the fixed driver in the disposable workspace; this is not proof
of hostile-candidate immutable-input handling. Normal output is one fixed bounded
byte string, not an implementation of W4B's TOML task.

The controller verifies zero VM host shares, exact image identity and PATH-only
container environment. It uses the existing read-only root, UID 65534, all caps
dropped, no-new-privileges, private process/cgroup namespace, network/IPC disabled,
1 CPU, 128 MiB memory+swap total, 16 processes and 1 MiB noexec tmpfs workspace.
No host mounts, repository, Docker socket, credentials, checker or oracle are
supplied. The fixed worker additionally checks socket/repository absence and
network denial. Those checks executed in the three final synthetic runtime cases;
the original failed arming attempts never reached them. This remains fixed-worker
evidence, not proof of arbitrary hostile-candidate containment.

## State and trust boundary

1. Exclusively create a mode-0700 per-job directory. Persist/fsync an ownership
   UUID, synthetic run/target/config, input/helper digests, controller PID and
   aware wall/monotonic observations before creation/start. Reserve identity
   before Docker create; bind its exact returned immutable ID before arming.
2. Verify exact container name, ID, ownership label, fixed command and containment
   policy. Copy the helper's exact source bytes and bind their digest. State
   readers reject symlinks, nonregular files, broad permissions and malformed or
   rebound identities. Operator-owned ancestors remain a trust precondition.
3. Bootstrap only one unique temporary `gui/<uid>` launchd label. Its intended
   worker watches controller exit through kqueue and the finite local deadline.
   No root daemon, login installation or global launch configuration is written.
4. Start only after the independent helper writes the exact lease/PID ready
   handshake. Fsync exclusive start consumption before the Docker start RPC.
   Existing state is recovery-only; no retry or second start resets the lease.
5. Intended cleanup checks immutable ownership, kills only that container,
   observes stopped state, reads a bounded output frame after stop, checks stable
   output and observed guest-process absence, removes the container and confirms
   absence through a successful daemon query. Command errors are uncertainty, not
   absence. This path passes the three bounded synthetic runtime cases below.
6. Recovery never launches work. It reuses a validated receipt or unloads only
   its helper and cleans up the same owned identity. Unknown/malformed ownership
   authorizes no kill. Failed cleanup retains state and blocks finalization.
7. Finalization independently verifies job removal, retains bound lease/receipt/
   output in a separate operator directory and removes known temporary state.
   Container cleanup and launchd-state disposal are separate checks. Neither a
   receipt nor a checksum authenticates a malicious external operator.

The receipt binds lease/run/target/config/container identity; input declaration
and whether it was actually observed; optional output digest/size; stop reason;
wall/monotonic observations; tracked guest PIDs; absence/stability flags and errors.
`canonical_attempt_latency` is always null. Preparation-to-stop intervals include
arming/control overhead; they are not inference latency or a hard execution-time
ceiling. Per-operation cleanup grace can extend the synthetic deadline. W4A's
frozen 600-second budget and acceptance remain unchanged. Synthetic control
receipts cannot validate as Observation, Verification or AdvisoryInput.
